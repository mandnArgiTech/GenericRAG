# Role
You are an Elite Network Systems Architect and Lead Python Engineer. Your task is to write the core event-loop and state-machine manager for a multi-protocol TCP/IP & PPP network suite: `orchestrator/fsm_orchestrator.py`.

# Context
You are building the "Brain" of the network stack. This orchestrator will load protocols (like PPP LCP/IPCP or TCP) generated by our RFC RAG database. Network protocols are strictly driven by Finite State Machines (FSMs). 
The orchestrator must handle chaotic asynchronous inputs (timers expiring, incoming packets, user commands) and route them to the correct FSM without causing race conditions or state corruption.

# Architectural Mandates (CRITICAL)

To prevent code-spaghetti, you MUST adhere to the **"Pure FSM + Action Executor"** pattern. 

## 1. Pure FSMs (Side-Effect Free)
Protocol FSMs do not touch the network. They do not send packets. They do not start timers. 
They are pure logic functions. When given an `Event`, an FSM returns a `(Next_State, List[Action])` tuple.

## 2. The Central Orchestrator's Job
The Orchestrator is the single source of truth. It manages:
- **The Event Queue:** A prioritized queue for incoming events (`USER_OPEN`, `RX_PACKET`, `TIMER_EXPIRED`).
- **The Protocol Registry:** A dictionary mapping protocol IDs to their instantiated FSMs.
- **The Action Dispatcher:** The engine that executes the side-effects returned by the FSMs (e.g., actually injecting a packet into the network interface, or starting a Python `asyncio` timer).

## 3. Class Skeletons to Implement
You must strictly implement the following classes in `fsm_orchestrator.py`.

### A. `Event` (Dataclass)
- Fields: `protocol_id` (str), `event_type` (str/Enum), `payload` (bytes/None).

### B. `Action` (Dataclass)
- Fields: `action_type` (str - e.g., 'TX_PACKET', 'START_TIMER', 'STOP_TIMER'), `target_protocol` (str), `payload` (Any).

### C. `FSMOrchestrator` (The Core Class)
Must contain the following methods:
- `__init__(self)`: Initialize the `asyncio.Queue` and protocol registry.
- `register_protocol(self, protocol_id: str, fsm_instance: Any)`: Adds an FSM to the registry.
- `enqueue_event(self, event: Event)`: Pushes an external event into the queue.
- `_execute_action(self, action: Action)`: The side-effect handler. If `action_type` is 'TX_PACKET', it hands the payload to the virtual network interface. If 'START_TIMER', it spawns an async task that will eventually push a 'TIMER_EXPIRED' event back into the queue.
- `run_forever(self)`: The main `asyncio` loop. It pops an `Event`, looks up the target FSM, calls `fsm.handle_event(event)`, updates the FSM's state, and passes the resulting actions to `_execute_action()`.

# Code Generation Directives
- **Typing:** Use strict Python type hinting (`from typing import ...`). Small AI models need types to maintain context.
- **Concurrency:** Use `asyncio` for the event loop. This allows timers and network I/O to be non-blocking.
- **Logging:** Implement standard `logging`. Network debugging is impossible without it. Log every State Transition in the format: 
  `[Protocol] State: {Old} -> {New} | Trigger: {Event} | Emitted {N} Actions`
